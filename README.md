# Gem Cutter MVP

Gem Cutter MVP is a local vertical slice for evidence-first commercial evaluation.

## What Is Implemented

- Opportunity project creation
- Evaluation run state machine
- Mock Source Adapters for web/news signals
- `RawSignal -> EvidenceItem -> EvidenceCluster -> ScoreLedger -> GateDecision`
- Markdown evaluation report rendering, with Markdown persisted in SQLite
- LLM PRD generation for `go` or `conditional_go` decisions, with template fallback in mock mode
- FastAPI endpoints and SSE event stream
- A professional React + Vite frontend workspace under `frontend/`
- The legacy static demo archived at `frontend/legacy/mvp-demo.html`

## Conda Environment

Use the existing `gem-cutter` conda environment:

```powershell
conda activate gem-cutter
python -m pip install -r requirements.txt
```

If the environment needs to be recreated later:

```powershell
conda env update -n gem-cutter -f environment.yml
```

## LLM And Search Configuration

The runtime reads JSON config from:

```text
config/settings.json
```

To keep using local mock data:

```json
{
  "llm": {"provider": "mock"},
  "search": {"provider": "mock"}
}
```

To use Ark Responses API with built-in web search, update `config/settings.json`:

```json
{
  "llm": {"provider": "ark"},
  "search": {
    "provider": "ark_builtin",
    "max_workers": 10,
    "per_dimension_workers": 2,
    "evidence_per_dimension": 5
  },
  "ark": {
    "api_key": "YOUR_API_KEY",
    "base_url": "https://ark.cn-beijing.volces.com/api/v3/responses",
    "model": "doubao-seed-1-8-251228",
    "timeout_seconds": 300,
    "stream": true,
    "enable_tool_choice": true,
    "max_output_tokens": 12000
  }
}
```

You can also override with environment variables:

```powershell
$env:ARK_API_KEY="YOUR_API_KEY"
$env:GEM_CUTTER_LLM_PROVIDER="ark"
$env:GEM_CUTTER_SEARCH_PROVIDER="ark_builtin"
```

## Run

```powershell
conda activate gem-cutter
python main.py
```

Then open:

- API: `http://127.0.0.1:8000/docs`

Run the official frontend workspace in a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Then open:

- Frontend: `http://127.0.0.1:5173`

The local development backend uses SQLite storage under:

```text
data/gem_cutter.db
```

Domain data is stored in dedicated SQLite tables rather than a JSON payload log. Reports are still served as Markdown through the API, and report Markdown is persisted on the `evaluation_reports` table instead of `data/reports/*.md`.

Ark calls use streaming by default. Each run writes model call logs into SQLite and exposes them through:

```text
GET /api/evaluations/{run_id}/llm-logs
```

The React frontend includes a professional workspace shell for projects, evaluation runs, reports, settings, and future evidence/score review workflows. Evidence search and LLM PRD generation both write model logs exposed by the backend.

PRD generation still requires a `go` or `conditional_go` Gate. In Ark mode, the PRD is generated by the LLM from the project, score ledger, evidence ledger, clusters, and Gate decision, then validated with a Pydantic schema before Markdown is stored.

Evidence search runs dimensions concurrently. Tune the concurrency with:

```json
"search": {
  "provider": "ark_builtin",
  "max_workers": 10,
  "per_dimension_workers": 2,
  "evidence_per_dimension": 5
}
```
