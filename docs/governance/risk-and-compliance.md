# Gem Cutter 风险与合规设计

> Status: Reference.
> Scope: 风险、合规、安全、质量门禁和人工复核策略。

## 1. 总体风险

Gem Cutter 的风险来自四类：信息来源风险、Agent 判断风险、自动开发风险、上线运营风险。项目必须以“可追溯、可复核、可回滚”为默认设计。

## 2. 信息来源风险

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 来源不可靠 | 社媒谣言、营销软文、重复转载 | 证据可信度评分、多源交叉验证 |
| 数据过期 | 热点已消退，报告仍引用旧数据 | 每个报告记录时间窗口和抓取时间 |
| 版权问题 | 抓取受限内容或复用受版权保护素材 | 标注来源，遵守平台规则，避免复制长篇原文 |
| 平台规则 | 违反 robots、API 条款 | 接入前配置数据源合规说明 |

## 3. Agent 判断风险

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 幻觉 | 编造市场规模、竞品、数据 | 强制证据引用，无证据标记为假设 |
| 过度自信 | 把粗估当确定结论 | 报告加入置信度和反证 |
| 范围失控 | 从评估直接跳到开发 | 阶段状态机和人工门禁 |
| 评分偏差 | 权重不合理或不适用行业 | 评分模型可配置，保留人工修正 |

## 4. 自动开发风险

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 代码不可运行 | 生成代码缺依赖或构建失败 | 沙箱构建和测试门禁 |
| 破坏本地文件 | Agent 写错路径或覆盖用户文件 | 沙箱隔离、工作区路径限制 |
| 密钥泄露 | 把 API key 写入代码或报告 | secret scanning、环境变量策略 |
| 依赖风险 | 引入恶意或不维护依赖 | 依赖审查和锁文件 |

## 5. 运营与舆情风险

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 误导性营销 | 自动生成夸大宣传 | 营销内容审核 |
| 负面扩散 | 产品问题引发投诉 | P0/P1 舆情告警 |
| 隐私问题 | 客户反馈包含个人信息 | PII 脱敏和权限控制 |
| 错误话术 | Agent 生成不当回复 | 高风险话术人工确认 |

## 6. 合规门禁

发布前必须检查：

- 是否涉及敏感行业：医疗、金融、法律、教育、未成年人、政治等。
- 是否包含未经授权的第三方素材。
- 是否处理个人信息。
- 是否需要隐私政策或用户协议。
- 是否存在平台 API 使用限制。
- 是否有误导性收益承诺。

高风险项目必须由人工确认，不允许自动发布。

## 7. 安全要求

- 所有外部数据源 token 存放在环境变量或密钥管理系统。
- Agent 沙箱不得默认访问宿主机敏感目录。
- 文件上传必须限制类型、大小和路径。
- 产物下载必须校验权限。
- 多租户版本必须做租户级数据隔离。
- Agent 工具调用必须记录审计日志。

## 8. 质量门禁

| 阶段 | 门禁 |
| --- | --- |
| 热点评估 | 至少 3 条有效证据，评分项可追溯 |
| 市场调研 | 竞品、用户、商业模式、风险均有结论 |
| PRD | MVP 范围、验收标准、不做范围明确 |
| 开发 | 构建通过或失败原因明确 |
| 测试 | 测试报告生成，P0/P1 问题关闭或豁免 |
| 发布 | 合规检查通过，有回滚方案 |
| 运营 | 活动目标和指标明确 |

## 9. 审计日志

必须记录：

- 用户请求。
- AgentRun 输入输出摘要。
- 工具调用。
- 数据源 URL。
- 报告版本。
- 人工审批动作。
- 评分修改记录。
- 发布动作。

## 10. 人工复核策略

必须人工复核的情况：

- OpportunityScore 高但证据可信度低。
- 涉及敏感行业。
- 涉及用户个人信息。
- 需要发布到公网。
- 出现 P0/P1 舆情。
- Agent 建议投入较高成本。
